# 3D Pose Audio Radar

## ローカル開発

Node.js 24 と Bun 1.4.3 を使用します。

```sh
bun install --frozen-lockfile
npm run dev
```

`npm test` で回帰テスト、`npm run lint` で型検査、`npm run build` で本番用の `dist/` を生成します。プルリクエストでもこれらを自動実行します。

開発サーバー起動前とビルド前に、インストール済みの MediaPipe パッケージから WASM・ローダーを `public/mediapipe/wasm/` にコピーします。これにより JavaScript と WASM のバージョンを揃え、アプリと同じドメインから配信します。生成ファイルは Git 管理対象外です。モデル本体は起動時に `storage.googleapis.com` から取得します。

スウィープは周期変調ホワイトノイズで利用できます。短い時計音・足音は固定位置で提示します。必要なランドマークの可視性が低い場合は方向の更新を止めます。頭部モードは鼻・両耳、肩モードは両肩、複合モードは両方を必要とします。肩幅連動距離では両肩も必要です。背面などで顔が隠れる場合は肩モードを選択してください。

## GitHub Pages

`.github/workflows/deploy-pages.yml` が `main` へのプッシュ時に型検査・ビルドを行い、成功した成果物を GitHub Pages にデプロイします。Actions タブから手動実行もできます。追加のデプロイ用シークレットは不要です。

リポジトリの **Settings → Pages** で以下を設定してください。

- **Build and deployment → Source**: **GitHub Actions**
- **Custom domain**: `pose-audio-radar.moukaeritai.work`（設定済みなら維持）
- 証明書の準備後に **Enforce HTTPS** を有効化（カメラ API の利用に必要）

公開先は https://pose-audio-radar.moukaeritai.work/ です。カスタムドメイン直下に配信するため、Vite の `base` は標準の `/` を使います。`public/CNAME` はビルド時に `dist/CNAME` へコピーされますが、Actions によるデプロイでのカスタムドメインは Settings → Pages で管理します。

## WHENet 頭部モード（実験）

停止中に「姿勢検出モデル」で **WHENet** を選び、カメラを起動します。YOLOX Nano が頭全体を自動検出し、WHENet がその切り出し画像から yaw・roll・pitch を推定します。肩・複合モードと肩幅連動距離は無効になり、距離は2.5m固定です。MediaPipe に戻すと、それまでの基準モード・距離設定を復元します。

- 最大の検出頭部1つを対象とします。1人で使用してください。人物の同一性を追跡する機能はありません。
- 紫色の枠は頭部検出結果、`HEAD DET` は検出器のスコアです。角度推定の信頼度ではありません。
- 検出スコア0.5未満・頭部未検出・カメラ映像が1秒以上更新されない場合は、既存の未検出時音声処理に切り替えます。推論が遅くてもカメラが動いていれば結果を採用し、結果の更新が観測した処理時間の2倍（最小1秒・最大30秒）以上止まった場合は未検出扱いにします。
- 推論は Web Worker 内の ONNX Runtime / WASM で行います。1度に処理するフレームは1枚で、停止・カメラ切替前の結果は破棄します。カメラ画像のサーバー送信はありません。映像は長辺640px以下の画素データとしてワーカーへ転送し、GPU の映像テクスチャの受け渡しには依存しません。
- 初回起動時のモデル・実行ファイルは合計約35 MB。GitHub Pages と同じドメインから読み込み、COOP/COEP ヘッダーや SharedArrayBuffer は不要です。Web Worker・OffscreenCanvas・WebAssembly SIMD が必要です。
- WHENet の元デモの回転行列を逆変換して、頭部から見たカメラの方向を音にします。画角は水平60°・垂直45°の近似です。頭部の角度、特に横顔・後頭部での精度、実カメラでの左右と上下の一致、スマートフォン上の速度は実機での比較が必要です。

低速な端末では `0.4 FPS` のように小数表示し、推論時間も表示します。初回の結果が返る前は「映像の取り出し・転送」「頭部検出」「角度推定」の進行状況を表示します。各工程が30秒を超えると工程名付きのエラーで停止します。推定に1秒以上かかる場合、動きに対して音が遅れるため、速い追従が必要なら MediaPipe を選んでください。

### モデルの取得・配信

`npm run dev` / `npm run build` の前処理で `scripts/prepare-whenet.mjs` を実行します。WHENet（約17 MB）と YOLOX Nano の配布アーカイブ（約253 MB）を取得し、SHA-256 を検証して必要な頭部検出モデル（約3.8 MB）だけを抽出します。初回ビルドには `tar` と外部への HTTPS 通信が必要です。Node.js の `--use-env-proxy` を指定しているため、クラウド環境の `HTTPS_PROXY` 設定も利用します。モデル・WASM は Git 管理せず、生成した `public/whenet/` を Pages 成果物に含めます。

再ビルド時はキャッシュしたモデルもハッシュ検証し、破損していれば再取得します。GitHub Actions でもこのディレクトリをキャッシュします。取得先は `github.com` / GitHub Release のリダイレクト先と `s3.ap-northeast-2.wasabisys.com` です。ダウンロード失敗やハッシュ不一致ではビルドを失敗させます。

出典・ライセンスは [NOTICE](public/licenses/whenet/NOTICE.txt) と同ディレクトリに収録しています。モデルの取得URLとハッシュは準備スクリプトに固定しています。変換済み WHENet の出力順 `yaw, roll, pitch` は、元の `WHENet.h5` の Dense 重みと ONNX の重みを照合して確認しました。

### 検証

`npm test` は前処理、頭部選択、角度の座標変換、単一フレームの非同期処理、未検出・古い結果の無効化、停止後の遅延結果の破棄、モデル読み込み失敗後の再試行を検証します。

Chromium 154 / Linux の配信用ビルドで、公式 WHENet の2つのサンプル画像を仮想カメラ入力にした実モデル推論を確認しました。正面側・後頭部側で自動検出、空画像で未検出、カメラ停止後のトラック解放、モデル切替と再起動が成功しています。これは動作確認であり、角度精度や実カメラ・モバイル端末の性能検証ではありません。
