# カメラタブ内での姿勢検出モデル切替および設定タブ連動の実装計画

カメラタブ内のヘッダーエリアに姿勢検出モデル（MediaPipe / WHENet）およびWHENet実行方式（GPU優先 / CPU固定）の切替UIを追加し、設定タブ（コントロールパネル）と双方向でリアルタイム連動させます。さらにカメラ実行中でも即座に自動再初期化を行い、シームレスに新モデルへ切り替わるホットスワップ機能を構築します。

## ユーザー確認および確定した決定事項

> [!IMPORTANT]
> ユーザー様からの回答に基づき、以下の仕様を確定しました。

- **確定事項 1（UI配置）**: カメラ枠上部のヘッダー右側（カメラ切替ボタンの横）に、洗練されたダークスタイルのセレクトボックスとして配置。
- **確定事項 2（稼働中切替動作）**: カメラ起動中（LIVE RUNNING中）であっても、停止を要求せず自動的に旧トラッカーを解放し、新モデルで再初期化してシームレスにトラッキングを継続。
- **確定事項 3（WHENet実行方式）**: WHENet選択時は、カメラタブ内にも実行方式（WebGPU優先／CPU固定）の切替セレクトを表示し、設定タブと完全連動。

---

## 1. 概要と提供価値

- **概要**: カメラタブの視覚的フィードバック（映像・FPS・推論時間HUD・スケルトン/バウンディングボックス描画）を見ながら、その場で直接 MediaPipe（全身骨格）と WHENet（頭部角度推定）を切り替えられるようにします。
- **対象ユーザー**: 3D立体音響レーダーの追従性や頭部/骨格検出精度、パフォーマンス（GPU/CPU負荷）を比較・検証するユーザー。
- **提供価値**: これまで設定タブに切り替えて変更していた手間を解消し、カメラ映像のリアルタイムな反応を観測しながらワンタップでモデル比較が可能になります。

---

## 2. ユーザー体験（UX）と視覚デザイン

### 主な操作フロー
1. **通常時（停止中）**:
   - カメラタブ上部のモデル選択プルダウンから「MediaPipe」または「WHENet」を選択。
   - WHENet選択時は即座に「GPU優先」「CPU固定」の選択肢が出現。
   - 選択内容は即座にローカルストレージに永続化され、設定タブ側も同時に同期更新。
2. **稼働中（LIVE中）**:
   - カメラが起動している最中にモデル（または実行方式）を変更。
   - モデル切替インジケータ（「モデル切替中...」と軽量スピナー）がヘッダーとプレビュー上に一時表示。
   - バックグラウンドで旧トラッカーが安全に破棄され、新トラッカーの初期化とビデオストリーム接続が完了次第、音声定位と骨格/頭部描画がシームレスに再開。
   - エラー発生時は分かりやすいトースト／アラートメッセージを表示して復旧を支援。

### デザイン仕様
- **カラー＆スタイル**: 既存のサイエンス・インスツルメント調（Obsidian `#020617` / `#0f172a`、ボーダー `#1e293b`、アクセント `#38bdf8` Sky）に統一。
- **タイポグラフィ**: `text-xs font-medium`、単一行（`whitespace-nowrap`）でレスポンシブに収まる幅設計。
- **モバイル対応**: スマホ画面幅でも「カメラ切替（イン/アウト）」と「モデル切替」が崩れず適切に折り返しまたはコンパクト表示されるFlexレイアウト。

## 3. 主要な設計上の決定とトレードオフ

- **状態管理の統合（Single Source of Truth）**:
  - *採用方針*: `App.tsx` のトップレベル状態（`trackingModel`, `whenetBackend`）を単一の情報源とし、カメラタブ（`CameraCanvas`）と設定タブ（コントロールパネル）の双方が共通のハンドラー関数（`handleSwitchTrackingModel`, `handleSwitchWhenetBackend`）を呼び出す設計。
  - *理由*: どちらのタブで変更しても確実に同期し、LocalStorageへの保存も漏れなく連動するため。
- **稼働中のホットスワップ処理**:
  - *採用方針*: `cameraOperationRef` による競合防止トークンをインクリメントし、非同期初期化中の重複実行や競合状態を防止しながら、既存のビデオストリーム参照を保持して新モデルへ再接続。
  - *理由*: 停止・開始ボタンを2度押す手間をなくし、快適な比較体験を提供するため。

## 4. 技術アーキテクチャ & 実装詳細

### システムアーキテクチャ図

```
┌─────────────────────────────────────────────────────────────┐
│                          App.tsx                            │
│  - State: trackingModel ('mediapipe' | 'whenet')            │
│  - State: whenetBackend ('auto' | 'wasm')                   │
│  - State: isSwitchingModel (boolean)                        │
│  - Handlers: handleSwitchTrackingModel, handleSwitchBackend │
│  - Storage: localStorage persistence (SETTINGS_STORAGE_KEY) │
└──────────────┬──────────────────────────────┬───────────────┘
               │                              │
       (Props & Handlers)             (Props & Handlers)
               ▼                              ▼
┌───────────────────────────────┐ ┌───────────────────────────┐
│     CameraCanvas.tsx          │ │   App.tsx (Controls Tab)  │
│  [Camera Header Bar]          │ │   [Tracking Model Panel]  │
│   ├── Model Select Dropdown   │ │    ├── Model Select       │
│   ├── Backend Select (WHENet) │ │    └── Backend Select     │
│   └── Camera Flip Button      │ └───────────────────────────┘
│  [Video & HUD Canvas]         │
│   └── Live Model Indicators   │
└───────────────────────────────┘
```

### 実装手順
1. **`App.tsx` のモデル切替ハンドラーの拡張**:
   - `handleSwitchTrackingModel`: 停止中・稼働中を問わずスムーズに状態を更新し、稼働中の場合は `isSwitchingModel` 状態を付与して新トラッカーの初期化＆カメラ再バインドを実行。
   - `handleSwitchWhenetBackend`: WHENetのバックエンド切替も同様にホットスワップ対応。
   - 設定タブ内の `select` 要素の `disabled={isRunning ...}` を解除し、稼働中ホットスワップハンドラーとバインド。
2. **`CameraCanvas.tsx` のインターフェース拡張**:
   - `trackingModel`, `onSelectTrackingModel`, `whenetBackend`, `onSelectWhenetBackend`, `isSwitchingModel` を props として受領。
   - ヘッダー右側のボタングループに、モデル切替セレクトボックスおよびWHENet用の実行方式セレクトボックスをスタイリッシュに実装。
   - 切替中のローディングフィードバック表示。
3. **ビルド検証**:
   - `compile_applet` によるTypeScriptコンパイル・ビルド確認。
